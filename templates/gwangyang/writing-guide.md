# 광양시 보고서·추진계획 작성 지침

적용: 로컬 kordoc의 `preset:report` 또는 `plan`, `agency:광양시`. 기본 1안, 사용자가 3색 띠를 지정하면 2안. 기관의 공식 표준을 선언하는 문서가 아니라 사용자 확인을 거친 작성 기준이다.

## 모델에 전달할 작성 지침

아래 지침과 사용자 제공 사실, 사용할 서식 부품의 입력 예시를 함께 제공한다.

> 광양시 업무 보고서 또는 추진계획 원고를 마크다운으로 작성한다. 사용자가 지정한 제목과 사실을 보존하고, 날짜·담당자·예산·일정·추진 실적을 지어내지 않는다. 미확정 사항은 미정 또는 협의 후 확정으로 표시한다.
>
> H1은 문서 제목, 제목 다음 첫 인용문은 짧은 보고요지, H2는 업무상 필요한 장으로 구성한다. 보고요지에 ‘보고 요지’라는 제목이나 ※를 붙이지 않는다. 요지는 목적과 핵심 조치를 담은 1~2문장으로 쓴다. 머리표가 그 사이에 있어도 요지 역할은 같다.
>
> 본문은 개조식으로 작성한다. 병렬 항목의 핵심을 빠르게 파악하는 데 도움이 될 때 `ㅇ (항목명) 설명`을 쓴다. 대상·기간·범위·방법·역할·산출물처럼 구분이 분명한 사항에 우선 적용한다. 모든 문장에 괄호 항목명을 강제하지 않는다. 항목명을 뺐을 때와 비교해 읽기 쉬운 쪽을 선택한다.
>
> 두 개 이상의 항목을 같은 관점으로 비교할 때 표를 쓴다. 주의사항·결정사항처럼 따로 묶을 이유가 있을 때만 설명상자를 쓴다. 제목 띠·번호칸·색·여백을 원고에서 공백이나 이미지로 흉내 내지 않는다. 서식과 피팅은 kordoc 코드에 맡긴다.
>
> 휴먼명조 행정문서의 가운뎃점은 `‧`(U+2027)를 사용한다. 장평·자간·폰트 크기를 모델이 임의로 조절하지 않는다. 요구한 쪽수는 작성 목표이며, 생성 후 실제 출력으로 확인한다. 넘치면 중복 문장을 줄이되 사실·조건·수치를 누락하지 않는다.

## 괄호 항목명을 선택하는 기준

| 문맥 | 선택 | 예시 |
|---|---|---|
| 사업 개요의 병렬 속성 | 사용 | `ㅇ (지원대상) 보고서 작성 담당자` |
| 역할·실행방법 구분 | 사용 | `ㅇ (검증방법) 생성 문서의 잘림‧겹침 확인` |
| 추진배경의 원인 설명 | 필요 없으면 생략 | `ㅇ 서식 편집의 반복 작업으로 작성시간 증가` |
| 장 제목과 같은 말 반복 | 생략 | ‘추진방법’ 아래 모든 항목에 `(추진방법)` 반복 금지 |
| 짧고 명백한 단일 요청 | 생략 | `ㅇ 부서별 검토 의견 제출` |
| 일정·담당·결과를 교차 비교 | 표 우선 | 단계 / 추진사항 / 완료 기준 |

항목명은 설명을 압축하는 짧은 명사구로 쓴다. `(기타)`, `(내용)`처럼 구분에 도움이 되지 않는 말은 피한다. 하위 세부사항은 `-` 수준으로 배치한다. 코드가 명시 부호를 해석하므로 항목 사이에는 빈 줄을 넣는다.

```markdown
## 지원 개요

ㅇ (지원대상) 보고서‧추진계획 작성 담당자

ㅇ (지원범위) 제목 띠‧설명상자‧본문표 등 14종

ㅇ (적용방법) 기관 스타일 선택 후 원고 입력
```

`ㅇ` 입력은 중항목으로 인식된다. 광양시 기본 출력 부호는 `○`이며 글리프까지 `ㅇ`로 유지하려면 `bullet2:'ㅇ'` 옵션을 명시한다. 괄호 항목명은 자동 굵게 처리되지 않는다. 강조가 필요한 경우에만 `ㅇ **(지원대상)** 설명`으로 입력한다.

## 서식 부품 선택

| 역할 | 입력과 선택 기준 |
|---|---|
| 대제목·장 제목 | `#`, `##` — 프레임이 제목 띠와 번호칸 생성 |
| 보고요지 | 첫 `>` — 제목 없는 무지 레터박스. 흰 캡션 설명상자와 구분 |
| 담당자 머리표 | 1안 `staff-header` — 제공받은 날짜·직위·성명·내선만 입력 |
| 일반 설명 | 1안 `box:white` — 이름을 붙여 묶을 필요가 있는 보충내용 |
| 주요 검토·조치 | 1안 `box:purple` — 별도 강조가 필요한 경우만 |
| 둥근 상자 | 1안 `rounded-box:plain/tab` — 짧은 개요·독립 설명. 한 쪽 이상이면 여러 상자로 나눔 |
| 기관 표지 | 1안 `institution-cover` — 별도 표지가 필요한 문서만. 기존 cover 옵션과 중복 금지 |
| 표·붙임 | GFM/HTML 표, `attachment`, `table-title` — 실제 비교·첨부 필요에 맞춰 사용 |

1안 전용 부품을 2안에 사용하지 않는다. 로고는 코드에 등록된 민선9기 자산을 사용한다. 14종을 한 문서에 모두 넣는 것을 목표로 하지 않는다.

## 생성과 검수

모델은 사실 정리·문장·위계·부품 선택을 담당한다. kordoc은 프레임·표·글꼴·부호·들여쓰기·장평·자간·높이 계산을 담당한다. 담당자는 실제 지면과 업무 사실을 확인한다. 피팅으로 내용이 자동 요약되거나 목표 쪽수가 자동 보장되지는 않는다.

입력 문법은 [README](README.md), 실행 가능한 2쪽 사례는 [원고](examples/05_추진계획_2쪽.md)와 `scripts/sample-gwangyang-plan.mjs`를 참조한다. 그 원고의 2쪽 검증은 현재 문안과 폰트 환경에 대한 결과다.

검수할 사항: 요지의 무지 상자, 머리표의 네 방향 선, 본문표 안 여백, 휴먼명조 `‧`, 제목·본문의 위계, 내용 누락, 쪽 경계 겹침. 기록허브의 2026-10-22 가운뎃점 사용자 지시와 이번 광양시 샘플 교정 내용을 반영했다.
