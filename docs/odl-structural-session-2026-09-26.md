1. **Docling** 표준 경로를 별도 venv에서 버전 고정 후 같은 200건에 직접 실행한다. Markdown 점수뿐 아니라 JSON의 블록 역할·bbox·원본 출처를 저장한다. 표제/목차 171·172·069·028·086·031·183·199와 079/080/156을 먼저 대조한다. 공식 CLI는 `--to md --to json`, OCR 영역 모드와 표 구조 엔진을 제공한다: [Docling CLI](https://github.com/docling-project/docling/blob/main/docs/reference/cli.md). **마크다운만 보고 영입하지 말고** 역할 신호가 공통 오류군을 실제로 설명하는지 확인한다.
2. **OpenDataLoader Hybrid**를 로컬 백엔드와 함께 직접 실행해 110/122/141 이미지·벡터 영역, 116/130 페이지 연결 표, 171 목차의 영역 구조를 살핀다. 하이브리드는 어려운 페이지를 백엔드로 보낼 수 있으며 공식 안내는 RAM 약 2~4GB·모델 디스크 1~2GB를 제시한다. 버전/백엔드/OCR/시간/RSS를 고정한다: [Hybrid Mode](https://opendataloader.org/docs/hybrid-mode). 기존 0.906572는 직접 재실행 성적이 아니다.
3. **Marker**의 기본/fast/필요시 하이브리드를 별도 환경에서 비교한다. 110/141의 시각 글·수식, 171 제목, 197 작은 표에 대한 JSON 역할과 읽기 순서에 주목한다. 코드와 모델 가중치의 사용 조건이 다르므로 제품 의존성 검토 전에 확인한다: [Marker 공식 README](https://github.com/datalab-to/marker/blob/master/README.md).
4. **MinerU**는 표·수식·레이아웃 JSON 후보로 직접 검증한다. 현재 프로젝트는 자체 라이선스를 표기하므로 채택 전 법적 검토와 모델 조건 확인이 필요하다: [MinerU pyproject](https://github.com/opendatalab/MinerU/blob/master/pyproject.toml), [빠른 시작](https://github.com/opendatalab/MinerU/blob/master/docs/en/quick_start/index.md).

모든 엔진은 **독립 설치·버전 기록·원본 GT/평가기 유지**로 실행한다. 엔진 전체 Markdown 선택이나 GT 기반 라우팅은 제품 설계가 아니다. 유망한 것은 영역 역할·셀 경계·줄 출처 같은 신호를 kordoc의 실제 기본 경로에 연결하고, 200건·한국·HWP 게이트에서 검증하는 것이다.
