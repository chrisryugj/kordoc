## 4.24.28 patch 붙인 글 서식 · 메모 · 2026-10-31

벤치 지표는 4.24.27 과 같다(`bench:gate` 전 단계 통과). patch 편집 반영 실험(4.24.25 와 같은 방식)의 반영 수는 그대로이고, 다시 읽어 서식까지 맞댄 검증 잔차가 줄었다:

| 실험 | 4.24.27 | 4.24.28 |
| --- | --- | --- |
| HWPX 글 편집 (117문서 · 540건) 검증 잔차 | 45 | **3** |
| HWP 5.x 글 편집 (30문서 · 140건) 검증 잔차 | 8 (파서 강조 반영 뒤 24) | **4** |
| 넓은 HWP 표본 (138문서 · 605건) 검증 잔차 | 2 (파서 강조 반영 뒤 37) | **0** |
| HWP 대체본 원본 서식 반영 (대체본 98건) | 90 | **94** |
| 같은 문서 HWP·HWPX parse 대조 (37짝) 다른 단위 | 390 | **118** |

잔차가 줄어든 까닭은 서식 run 끝에 붙인 글이 굵게·위첨자를 물려받던 것을 마크다운 서식대로 넣게 고쳐서다. HWP 4.24.27 잔차가 적었던 건 HWP 파서가 굵게를 내지 않아 서식 차이가 보이지 않았기 때문이다 — 파서가 강조를 내면서 드러난 24·37 을 4·0 으로 줄였다. 남은 7건 가운데 5건(HWPX 2·HWP 3)은 균등 배분으로 띄어 쓴 짧은 제목("재 무 상 태 표")에 붙인 낱말을 파서가 균등 배분으로 보고 이어 읽는 꼴이고, HWPX 1건은 표 캡션(원문 글 찾기로 고쳐 서식을 맞추지 않는다), HWP 1건은 같은 문단 넷이 11만 5천 문단에 걸쳐 되풀이되는 부하 시험 문서가 레코드 상한(50만 개)에 걸려 고친 뒤 끝 문단 하나를 더 읽는 꼴이다. 캡션 말고는 문서가 의도대로 바뀐다.

## 4.24.26 HWP → HWPX 변환 · 2026-10-31

HWP 5.x 를 HWPX 로 서식 그대로 옮기는 변환(`kordoc to-hwpx`·MCP `convert_to_hwpx`)을 새로 잰다(`node bench/hwp2hwpx.mjs`, `bench:gate` 무후퇴 게이트).

- 정답: 같은 문서를 한글이 .hwp·.hwpx 로 함께 저장한 짝. 같은 이름·같은 판(한글 미리보기 글이 같음)이고 HWPX 가 한글 저장본인 것만 쓴다 — 다른 변환 도구가 만든 HWPX(853건)는 결과를 보기 전에 정한 규칙으로 뺀다. 264짝, 속성 대조는 한글 2020 이상 형식(xmlVersion 1.5) 232짝.
- 채점: header·section·masterpage XML 을 트리째 맞대 속성 값과 글 마디 단위로 같은 비율(빠지거나 덧붙은 마디도 모수에 든다).

| 지표 | 결과 |
| --- | --- |
| 속성 일치 (232짝) | **0.99194** (header 0.98193 · section 0.99763) |
| 글 일치 (264짝) | **264/264** |
| 완전 일치 | 14/232 |

남은 차이는 대부분 HWP 에 없는 정보다 — 정답을 저장한 한글 판(한글 2024 만 쓰는 textDir, 8수준 제목 표기), 한글이 돌던 컴퓨터의 글꼴 대체, 두 파일을 저장한 사이의 편집. 한글(맥)에서 원본 HWP 와 변환본을 나란히 열어 80문서를 대조했고(1쪽·상태줄의 쪽/글자/구역 수·여러 쪽 화면) 모두 열렸으며, 차이가 난 문서는 원인을 고쳐 같아졌다(아주 큰 문서 1건은 쪽 나누기 전에 찍혀 판정에서 뺌).

patch 편집 반영 실험의 HWP 5.x 글 편집은 탭·필드가 든 문단을 바이트째 고치게 되어 123 → **132**/140 이다. 나머지 벤치 지표는 4.24.25 와 같다.

### OCR 표 점수 읽는 법

OCR 표 정답은 같은 PDF 텍스트층을 kordoc 파서로 읽은 표라, 화면에 보이지 않는 칸 경계·배치용 틀까지 들어 있다. 4.24.24 기준 미달 33표 가운데 20여 표는 그림만으로는 맞힐 근거가 없는 경우다(법정 서식의 촘촘한 정답 격자 14 · 목차·배치용 틀 약 6 · 선 없는 상자 3 · 예산서 들여쓰기 빈 열 약 2). 실제 OCR 쪽 오류(칸 배정·머리 행·열 묶기)는 8표 안팎이다. 채점은 공개본(HF `Chrisryugj/kordoc-ocr-bench`)과 같게 두고 바꾸지 않는다.

중첩표 100%는 위 텍스트층 표본에 한정하며, 텍스트층 없는 PDF·OCR 및 전체 조판을 포함하지 않습니다. PDF 전체 글 커버리지는 OCR 전용 114건과 약한 텍스트층 68건을 별도로 분류한 모수입니다. OCR은 216dpi 렌더와 같은 PDF의 텍스트층을 비교한 결과로 실스캔의 노이즈·기울기 정확도가 아닙니다. 테스트 3,940통과·9스킵, 타입검사·빌드·전체 자동 게이트를 통과했습니다.

## 한국 공문서 — 원본 HWPX 를 정답으로

HWPX 원본과 그 문서를 PDF 로 내보낸 파일이 짝으로 있는 실제 정부 문서(보도자료·결재문서·법령 서식·예산서 등)로, 원본을 정답 삼아 PDF 에서 뽑은 글과 표를 잽니다.

### 채점 기준

2026-09-29 정비, 2026-09-30 보이는 표 기준 도입, 4.18.1 참조 추출기 정정 이력은 [CHANGELOG](../CHANGELOG.md)에 기록돼 있습니다. 참조 정정과 실제 입력란 보존 수정은 [원본 감사](release-4.18.1.json)에서 구분합니다.

**표 정답 = 원본에서 보이는 표** (v4.17.0)
- 칸 테두리(header.xml borderFill, 선 종류 NONE·흰 선은 안 보임)가 그리는 모습대로 나눕니다(`bench/ref/visible-tables.mjs`, 파서와 코드 공유 0%).
- 세로선이 보이는 행과 온 폭 가로선 사이 칸 둘 이상인 행이 표 행, 이어진 표 행 묶음 하나가 보이는 표 하나. 나머지 행은 글(글 재현율에는 그대로).
- 어느 칸 모서리도 안 쓰는 격자선·보이는 변 밖 빈 들여쓰기 칸·선 없는 빈 여백 행·후행 빈 열은 접습니다.
- 칸 두 개와 가로선으로 조립한 분수는 수식(글 모수에서 빼고 수식 존재 모수에 1개). 표 온 폭 두 칸은 2×1 표일 때만.
- 법령 별표 한컴 PDF 그림 대조(원본 그림 66쪽, 보이는 표 50개): 일치 42/50, 여백 행(A1)·분수 오탐(P1) 보정 뒤 48/50. 남은 2개는 이어쓰기 행·공식 상자 각 1건이라 규칙을 두지 않았습니다.

**법령 별표** (`bench/annex-gt.mjs`)
- 법제처 별표 272건(licbyl-byl·licbyl-byl2)의 HWP 원본과 한컴 PDF 를 같은 정답으로 잽니다. PDF 는 `ocr: false`(법령 MCP·lexdiff 서버와 같은 조건).

**PDF 글**
- 읽기 순서: 같은 글이 여러 번 나오는 줄은 순서가 맞는 등장 자리로 봅니다.
- 떠 있는 글상자, 글자·숫자 없는 줄(마스킹 "*****")은 순서 채점에서만 뺍니다.
- 양쪽 평문에서 목록 표지 "- " 와 각주 감싸개 "(주: …)" 괄호를 걷습니다.

**PDF 글·표 모수**
- 원본과 다른 판(PDF 글이 3배 초과)인 쌍은 뺍니다.
- PDF 텍스트층(pdftotext)이 정답 글자의 93% 를 못 담은 쌍(렌더 결함 재현본 등)은 뺍니다.
- PDF 커버리지는 리더 점 런을 지웁니다.

**OCR**
- 표본 쪽을 고정합니다(`bench/ocr-pages.json`).
- 텍스트층 글이 없는 그림 영역의 OCR 글은 글자 대조에서 뺍니다(본문 블록에 섞인 로고 글은 그림만 따로 읽어 설명되는 잉여만).
- 그려지지 않은 텍스트층 글(흰 글·덮인 글)은 글자 대조에서 뺍니다.
- 글줄 안 글자를 그림으로 찍은 쪽은 표본에서 뺍니다.
- 픽셀로 못 가르는 글자는 접습니다 — 가운뎃점 · • ∙, 단위 ㎡ 와 m², 낫표 ｢｣ 「」.
- 값 칸이 여러 줄로 나란히 쌓인 표 행은 줄 번호별로 펼칩니다.

## HWP·HWPX → Markdown — HwpForge 비교

같은 코퍼스를 [HwpForge](https://github.com/ai-screams/HwpForge) 0.16.6(`to_md`, lossy)과 kordoc 으로 변환해 **원본 HWPX XML 을 정답**으로 같은 채점기에 넣었습니다. 표는 두 출력 모두 같은 Markdown 표 파서로 격자화하고 1열 표는 뺐습니다.

- **표 점수 차이** — HwpForge 는 생성·편집 중심이고 Markdown 표가 파이프 표뿐이라 병합 칸을 못 나타냅니다.
- **1열 표를 뺀 이유** — 1열 표(1,288개)는 제목·본문 상자 43%·빈 여백 틀 28%·목록형 3% 인 꾸밈 틀이라 표/줄 글은 표현 선택이고, 그 글은 글 재현율이 채점합니다. 1열 표를 넣으면 HWPX 10,392표 kordoc 90.6%·HwpForge 36.0%, HWP 3,500표 92.8%·32.1%.
- **HWP 문서 수** — 짝 HWPX 가 배포용 암호라 정답이 없는 1건을 뺀 값입니다.
- **재현** — `bench/hwpforge-bench.py` → `node bench/compare-md-parsers.mjs <출력 폴더>`(1열 표 포함은 `--include-single-col`).
