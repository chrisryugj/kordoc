## 유저 결정 (2026-10-09)

1. **마크다운 `<u>` 유지** — 한컴·법령 문서의 밑줄은 개정·강조 표시라 원본 정보다. ODL 200 에서 18문서가 이 표기로 깎이지만(빼면 0.9582 → 0.9589)
   기본 출력에 둔다. 색인·RAG·벤치용은 `plain: true`.
2. **MCP `fill_form` 에 `fields_file` 추가 + 응답 마스킹** — 값을 JSON 파일로 받아 도구 인자(대화 맥락)에 남기지 않고, 파일로 받은 값은 응답에 글자 수만.
3. **그림 영역 자동 OCR 범위 유지** — 글 없는 큰 그림(쪽 면적 5%+)만. `ocr: true` 범위(2%+·쪽 머리 로고)로 넓히면 ODL +0.0015(8문서↑·0↓)지만
   한국 문서 로고 글 잡음·지연을 피한다. 차트 OCR 이 쓰레기 글·가짜 표를 만드는 문서(124·140)는 범위와 별개로 버그로 고친다.

## 4.18.6 → 4.21.3 ODL 회귀 (2026-10-09 추적)

같은 채점기로 4.18.6(`v4.18.6` 체크아웃 빌드)과 4.21.3 을 문서별로 견줬다(`suite.mjs cmp v4.18.6 base-4.21.3`).

- `ocr: false`: 0.93715 → 0.93611, 하락 문서는 **039 하나**(NID 0.987 → 0.721).
- 기본(자동 OCR): 0.96045 → 0.95819, 하락 10·상승 12. 큰 하락 141(NID 0.962 → 0.444)·039·110(TEDS 0.9995 → 0.977)·140·128·134·057·100·115·098.
- 원인: **624007d `fix(ocr): keep one visual line together and stop item rows merging (#141)`** (GitHub #141 영수증 OCR 수정). bisect 와 파일 단위 되돌림으로
  확인 — 039 는 `startsNewRecord`(위 행이 한 칸 산문이어도 다음 줄을 새 레코드로 봐 두 단 본문 줄이 병합되지 않고 산문 표 판정을 비껴감),
  141 은 `groupOcrLines`(두 단 카드의 좌우 줄·QR 잡음 상자 "다|i" 를 한 줄로 묶어 쪽 단 분리가 깨짐)와 `startsNewRecord` 둘 다.
  표 개수로 bisect 하다 GFM `| ---`/HTML `<table>` 를 섞어 세어 헛짚었다 — 문서 하나도 ODL 채점기 점수로 판정한다(스크래치 `odl1.sh`).
