# 개조식 보고서 문체 — 검수 규칙과 실측 근거

서식이 맞아도 문체가 다르면 그 부서 문서로 읽히지 않는다. 표기법 검수(`gongmun-lint.ts`,
행정업무운영 편람 13룰 + v4.12.1 보강 6룰)가 **어떻게 적는가**를 본다면, 문체 검수(`munche-lint.ts`)는
**어떤 꼴로 끝나는가**를 본다.

개조식은 서술형 문장이 아니라 **명사구로 끝나는 짧은 줄을 층층이 쌓는 문체**다.

## 근거

지자체 실무부서의 요약보고·기본계획·검토보고 **15건(2,288줄)** 실측 통계 —
[jkf87/hwpx-skill](https://github.com/jkf87/hwpx-skill) v1.17.0 이 `references/bogo-munche.md`
로 공개한 수치를 임계값 근거로 삼았다. 규칙 코드·정규식·판정 로직은 kordoc 자체 구현이다.

| 층 | 줄 수 | 중앙 글자 | 종결 |
|---|---|---|---|
| □ 소제목 | 72 | 22 | 2~4어절 명사구 |
| ❍ 항목 | 264 | **31** | 명사·명사구 (`필요·운영·조성·가능·지원`) |
| - 세부 | 307 | **48** | 명사구 + `~함/있음` 16% |
| ⇒ 결론 | 24 | **30** | 명사 종결 |

**항목이 세부보다 짧다** — 항목은 제목처럼, 세부는 설명처럼 쓴다.

핵심 실측 셋:

- 서술형 `~다` 종결: **0%** (항목 0/264, 세부 1/305, 결론 0/23)
- `A가 아니라 B` 식 수사: **0건** — `아닌` 12건은 전부 두 구체 선택지를 가르는 것
- 물음표·느낌표: 본문 **0** (인용문 안에만 3·4건)

## 규칙

| 코드 | 등급 | 무엇을 잡는가 | 고치는 방향 |
|---|---|---|---|
| `DA_ENDING` | error | `~다` 서술형 종결 | 명사·명사구 또는 `~함/있음` |
| `DEONTIC` | error | `~해야 한다` 당위 종결 | `⇒ ○○ 필요` |
| `RHETORIC_CONTRAST` | error | `아니라 B` 의 B 가 추상어·가치어 | 지우거나 구체 선택지로 |
| `CONTRAST_CHECK` | warning | `아니라 B` 의 B 가 구체어 | 확인만 — 제도·장소·절차면 정상 |
| `QUESTION_EXCLAIM` | error | 본문의 물음표·느낌표 | 지움 (인용 안은 예외) |
| `GEOSIDA` | warning | `~것이다/것임` | 명사 종결 |
| `COUPLET` | warning | 대구(對句) 슬로건 | 목표 수치·명사로 |
| `ITEM_LONG` | warning | 항목 70자 초과 | 근거·예시는 세부(`-`)로 내림 |
| `CONCL_LONG` | warning | 결론 60자 초과 | 판단 하나만 남김 |
| `LEAD_ENDING` | warning | 리드문이 `~하고자 함.` 이 아님 | `[수단]하고, [수단]하여 [목적]하고자 함.` |
| `LEAD_LONG` | warning | 리드문 140자 초과·두 문장 이상 | 수단 둘·목적 하나로 압축 |
| `DATE_KOREAN` | warning | `2026년 8월` 글자 표기 | `2026. 8. 22.` |

줄표(`—`)·강조 남발은 표기법 검수의 `AI_EM_DASH`·`AI_BOLD_OVERUSE`(v4.9.0)가 이미
잡으므로 여기서 중복하지 않는다. 날짜 온점·금액 단위 같은 표기법도 `gongmun-lint.ts`
가 SSOT다.

## 적용 범위

문체 검수는 **보고서·계획서·개조식** 프리셋에서만 돈다(`usesGaejosikMunche`).

- 기안문·시행문(`official`)은 경어 종결(`~하시기 바랍니다`)이라 `~다` 룰이 오탐이다
- 통지·회의록·보도자료도 각기 문체 관행이 달라 제외한다

범위를 좁히는 것이 오탐을 막는 가장 확실한 수단이다.

## 쓰는 법

```bash
# 생성 시 — 보고서·계획서·개조식 프리셋이면 자동으로 경고가 붙는다 (생성은 막지 않음)
kordoc generate 원고.md -o 보고서.hwpx --preset 보고서

# 원고만 검수 — 표기법은 기본, 문체는 --munche 로 옵트인
kordoc lint 원고.md
kordoc lint 원고.md --munche
kordoc lint 원고.md --munche --json
```

라이브러리에서는 `lintMuncheText(text)` 가 `MuncheLintFinding[]` 을,
`muncheLintWarnings(text, limit)` 가 사람이 읽는 경고 문자열 배열을 준다.

## 줄 종류 판정

같은 문장도 층에 따라 허용 여부가 다르므로 줄마다 종류를 먼저 가른다. 원고는 두 꼴로
오는데 둘 다 받는다 — 개조식 부호를 직접 쓴 것(`□ ○ ❍ - ⇒ ※`)과 마크다운 목록으로
계층을 표현한 것(들여쓰기 깊이).

`□` 소제목과 `※` 참고는 명사구 제약 밖이고, 헤딩·표·코드펜스·YAML 프런트매터는 검사하지
않는다. 인용부호와 괄호 안은 원문 인용이라 종결·수사 판정에서 제외한다.
