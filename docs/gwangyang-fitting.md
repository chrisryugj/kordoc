> 현재 표 정책: 글자취급, 바깥 여백 0, 호스트 문단 앞4pt·뒤8pt. 아래 18쪽 장문 시각 검증은 부유 본문표를 사용했던 이전 결과이며 현 정책의 장문 표 쪽나눔을 보증하지 않는다. 한 쪽보다 긴 글자취급 표는 분할 입력이 필요하다. 현재 2쪽 작성 사례와 속성 회귀 테스트는 최신 설정으로 확인했다.

# 광양시 14종 피팅 통합 검증

2026-10-26. 사용자 지시: 14종을 기존 피팅 체계에 연결하되 서식 모양 유지.

## 적용 범위

| 에셋 | 기존 체계 연결 | 넘치는 경우 |
|---|---|---|
| 1·2안 대제목, 소제목 | fitOneLine + autoFit.minRatio/safety | 글자 크기 고정, 줄바꿈·제목표 높이 증가 |
| 붙임 머리표, 밑줄 표 제목 | fitOneLine | 번호/제목 영역 너비 유지, 줄바꿈 |
| 흰·보라 설명상자 | 캡션 fitOneLine, 본문 fitCharBreaks → fitParagraph | 실제 표시 문안의 장평·자간을 높이 추정에도 적용. 긴 상자는 캡션을 반복한 동일 형태 상자로 분리 |
| 일반·제목 탭 둥근 상자 | 본문 fitCharBreaks → fitParagraph, 탭 fitOneLine | 도형 높이와 탭 높이를 늘림. 한 쪽 한도 초과는 명시적 오류 |
| 담당자 머리표 | 날짜·직위·성명 fitOneLine | 담당자별 같은 행 높이. 성명+내선이 길면 내선 전체를 다음 줄로 이동 |
| 기관 표지 | 제목·부제·메타정보·결재직위·부서명 fitOneLine, 요약 fitParagraph | 셀 높이 증가. 요약 높이 한도는 유지 |
| 1·2안 본문표 | 기존 공통 gen-table 열폭·행높이, gen-gongmun 표 크기 조정 | 기존 표 엔진 동작 유지. 별도 기관 전용 표 압축 엔진을 만들지 않음 |

공통 전달 경로: `ResolvedGongmun.autoFitMinRatio/autoFitSafety` → `FrameCtx.fit` → `fitGwangyangText` → 기존 피팅 함수. `autoFit:false`는 새 부품의 장평100/자간0을 유지한다. 일반 표의 기존 열폭·크기 계산까지 끄는 옵션은 아니다.

새 부품은 본문/제목의 pt를 낮추지 않는다. 번호칸·색·테두리·로고·가로폭을 유지하며 세로 높이는 내용에 맞춰 바뀐다. 인라인 마크다운 기호를 제외한 표시 문자열로 계산한다. 피팅은 목표 쪽수 강제 기능이 아니다.

## 작성 테스트

`scripts/test-gwangyang-fitting.mjs`는 통합 카탈로그의 4개 원고를 긴 문안으로 바꾸고 ON/OFF 각각 생성한다. 14종 입력 커버리지, OFF 압축 없음, ON/OFF의 borderFill/이미지 SHA256 일치 검사를 수행한다.

| 문서 | OFF | ON |
|---|---:|---:|
| 기본 7종·장문 병합표 | 3쪽 | 3쪽 |
| 머리표·둥근 상자 2종 | 1쪽 | 1쪽 |
| 기관 표지·장문 보고서 | 3쪽 | 3쪽 |
| 2안 제목·소제목·장문 표 | 2쪽 | 2쪽 |

한글 COM으로 8문서 총18쪽 출력 후 시각 대조. 기본 4샘플도 재생성·출력하여 기존1/1/2/1쪽 유지 확인. 긴 문장의 끝문구 수를 입력과 PDF에서 대조해 16/4/9/2개가 ON/OFF 모두 보존됨을 확인했다.

검증 중 발견한 떠 있는 설명상자와 뒤 표의 쪽 경계 겹침을 수정했다. 최초 ON2쪽 결과는 겹침이 있었으므로 폐기했고, 최종 ON3쪽을 유효 결과로 삼았다. 긴 상자는 본문 흐름에 들어가는 묶음으로 분리한다. 한 항목 자체가 한 쪽보다 긴 입력은 잘라 내지 않고 여러 body 항목으로 나누도록 오류를 낸다.

- 회귀 테스트 266개 통과. typecheck/build/diff-check 통과.
- 신규 테스트: 기존 fitParagraph 결과 일치, autoFit false/minRatio/safety, 마크다운 표시폭, 긴 상자 분리·문단 보존, 과대 문단 오류.
- 실제 파일: `output/gwangyang-fitting/`. ON/OFF 합본 각9쪽, HWPX8개, 원고·옵션·JSON·로그 포함.
- `fitting-results.json`, `hancom-export.json`, `pdf-content-check.json`, `xml-validation.json`, `test.log`가 검사 근거다.

자동 피팅으로 문안의 의미를 바꾸거나 임의로 삭제하지 않는다. 아주 긴 둥근 도형은 분할 입력이 필요하고, 다른 용지·폰트·여백은 별도 지면 확인이 필요하다.
