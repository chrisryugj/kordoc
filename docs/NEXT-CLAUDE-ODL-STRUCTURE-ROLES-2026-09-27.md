## 2. 작업 순서 (위에서부터, 단계마다 200건 전체 재채점과 문서별 증감 기록)

### A. 표 경계 확장 (ODL TEDS 0.766, 가장 큰 미개척 축)
- **047**: 선 격자가 데이터 행만 감싸고, 괘선 없는 머리행 2줄과 `Total` 행이 격자 밖에서 따로 가짜 표가 된다. 격자 바로 위·아래에 붙은 줄의 아이템이 격자 열 범위에 떨어지면 행으로 흡수하는 **격자 행 확장**을 만든다. 한컴 PDF는 클립이 진실이므로 클립 격자에는 적용하지 마라.
- **116·190**: 지난 세션 `isProseLine`이 표 사이 문장 줄에서 영역을 끊어 구조는 맞아졌지만, 뒤따르는 작은 표(한 아이템 머리행 + 1행)를 최소 3행 조건으로 버린다. 같은 쪽 앞 표와 열 앵커가 같은 2행 영역을 허용하고, 한 아이템으로 붙은 머리행은 앞 표 열 경계로 쪼갠다.
- **130·127**: 클러스터 표에 값 없는 사이 열이 끼어 5·7열이 된다(정답 3·4열). 모든 행에서 비어 있는 열을 열 경계 재계산으로 제거한다.
- **170·180·045·119·200·182**: 원문 렌더와 GT를 나란히 보고 공통 원인군을 먼저 묶어라.
- 한국 쪽: 표 실패 목록을 `bench/out/pdf-table.json`의 `details`에서 다시 뽑고(행만 틀림/열만/양축/미매칭), `156775700` 점선·5.64pt 머리행, `156775701`, `pii_bunseok`, `tac-img-02`, `scattered_header`를 같은 격자 경계 문제로 다뤄라. **exact +9가 필수선이다.**

### B. 그림이 낀 두 단 지면 (NID 0.055)
- **013·009**: 그림·캡션이 단 안에 있어 오른쪽 단 글이 더 위에서 시작하면 먼저 읽힌다. 이미지 영역(`extractImageRegions`)을 거터 판정의 점유 사각형으로 넣어 쪽 전체 거터를 확정하고 좌단 전체→우단 전체로 읽어라. 지난 세션 `local-regions.ts` 경로와 충돌하는지 먼저 확인.
- 3-09월_교육_통합_2023 order −0.056(격자 쪽 조기 두 단 판정 부작용)을 같이 해결하라.

### C. 제목 (MHS 0.874)
- 남은 오탐: 183·199·200 슬라이드 제목류, 086 저자 줄, 156 라이선스 각주, 069 `In-store Sorting…`, 028 `Definition 1.` 줄(줄 앞 굵은 글자만 다른 서체). **줄별 서체 순도**를 IR 블록에 남겨 "앞부분만 굵은 문장"을 제목에서 빼라.
- 남은 미탐: 021 `2`, 117 `Employing Steps…:`, 037은 해결됨. 118 사이드바 라벨은 본문보다 작아 원칙과 충돌하니 근거 없이 규칙을 만들지 마라.
- 강등된 `① …`, `3) …` 문장이 한국 목록 글머리 `- `로 나와 precision이 5건 떨어졌다. 목록 감지가 제목 강등 블록을 어떻게 받는지 정리하라.

### D. 이미지 속 글 (141·110·027·148·107·122)
기본 경로에서는 글층이 없다. 명시적 OCR 점수를 먼저 재고(이번 커밋 기준 미측정), 기본 경로 자동 OCR 도입 여부는 시간·RSS·모델 준비·미설치 동작을 수치로 제시한 뒤 사용자에게 결정을 받아라. 임의 도입 금지.

## 3. 운영 규칙 (지난 세션에서 실제로 사고 난 것들)

- **게이트 중 재빌드 금지.** 한국 게이트는 별도 worktree에서만 돌려라:
  `git worktree add /private/tmp/kordoc-gate-wt HEAD`, `node_modules`와 `bench/corpus`를 심링크, 후보마다 `rsync -a --delete src/ tests/`로 동기화 후 그 안에서 build·gate. 같은 저장소에서 게이트 도중 빌드해 측정 1회가 무효가 됐다.
- 기준선 비교용 worktree(`/private/tmp/kordoc-base-wt`, HEAD 빌드)를 만들어 문서별 Markdown diff를 직접 보라. 문서 하나는 `node bench/pdf-table-gt.mjs --no-ocr --doc=<이름>`, `node bench/pdf-text-gt.mjs --doc=<이름>`으로 빠르게 잰다.
- A/B는 임시 환경변수 토글로 같은 빌드에서 비교하고, 채택 결정 뒤 토글·계측(`console.error` 디버그)을 반드시 지운다. 커밋 전 `grep -rn "KORDOC_DEBUG\|KORDOC_NO_" src/`가 0건이어야 한다.
- ODL 채점: `node bench/odl-bench.mjs <새_디렉터리>`(디렉터리에 `pdfs` 심링크) 뒤 `<ODL>/.venv/bin/python <ODL>/src/evaluator.py --prediction-root <절대경로>/prediction --engine kordoc --output-filename evaluation.json --log-level ERROR`. 채점은 3초면 끝나니 후보를 잘게 쪼개 자주 재라.
- 규칙 하나를 넣을 때마다 **어느 한국 문서가 움직이는지** 확인하라. 지난 세션 반증 사례: 클립 표 잇기(편람 −40표), 산문 표 거부(설명 긴 3열 표 소실, 옛 열 표 경로가 쪽 전체를 한 표로), 차트 희소 조건(전화번호 연락처 표). 전부 한국 게이트로만 드러났다.
- GT 문구·문서 ID 규칙, PDF/GT/평가기/제외 모수 변경 금지. 같은 접근 3회 실패 시 가설 재수립.
