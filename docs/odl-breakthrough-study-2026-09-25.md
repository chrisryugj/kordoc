## 다음 설계 게이트

1. 텍스트 조각·괘선·채움·이미지 후보를 **줄 병합 전** 같은 좌표계의 영역 노드로 구성한다. `040`·`043`의 탭으로 합쳐진 두 단, `181`의 전폭 제목+복수 칼럼을 개발 표본으로 삼는다. 블록 후처리만으로는 기존 `bbox` 하나에 섞인 글자 위치를 복구할 수 없다.
2. 제목 후보에는 원본 줄의 스타일 분포를 보존한다. 현재 `pushLineParagraphs`가 여러 줄과 스타일을 한 블록으로 병합하고 `detectTypographyHeadings`는 페이지에 크기 기반 제목이 하나라도 있으면 그 페이지 전체를 건너뛴다. 문서 전체 스타일 군집과 제목/본문 분리를 함께 검증한다.
3. 셀 그래프는 1열 다행도 표현한다. 현재 `page-blocks.ts`는 1열 다행 괘선 격자를 건너뛰고, `table/builder.ts`는 그 IR도 본문 줄로 평탄화한다. `149` 같은 실제 데이터 표와 한국 서식의 1열 레이아웃 틀을 **선 연결·행별 채움·글 배치·표 외부 문맥**으로 구별해야 한다.
4. 영역별 텍스트 커버리지·이미지 점유·열 정렬 충돌로 OCR/시각 후보를 제한하고, 원본 글자가 있는 칸에는 OCR 글자를 덮어쓰지 않는다. 3건의 기존 페이지 전체 OCR 결과는 비용/이득 기준이다.

각 통합 변경 뒤에는 원본 200건과 한국 PDF 표 716쌍·글 751쌍, 중첩표, HWPX/HWP5, 시간·최대 RSS를 다시 측정한다. 0.85/0.90 중간 게이트를 못 넘으면 기본 경로에 합치지 않는다. 현재 0.93 목표는 달성하지 못했다.

넓은 1열 상자를 후보 단계에서 제외하고, 글이 있는 행의 평균 높이를 함께 판정한 수정 후 ODL 점수는 **0.778099** 그대로(개선 `149` +0.549054, 악화 0)였다. 200건 시간 7.11초·최대 RSS 831.6 MB. 영문 출판 계약서와 개인정보 동의서 Markdown은 기준선과 byte 동일함을 확인했다. 앞선 후보의 `bench/score.mjs`는 HWPX 2,286건·표 13,041/13,041·중첩 2,161, HWP5 1,120쌍·표 4,237/4,237·실패 0, PDF 1,911건 coverage 0.99778로 모두 PASS(528초). 수정 후보의 한국·형식 게이트는 진행 후 수치를 확정한다.

### Microsoft MarkItDown 비교 (사용자 추가 요청)

[Microsoft MarkItDown v0.1.8](https://github.com/microsoft/markitdown/releases/tag/v0.1.8)을 별도 Python 3.12 가상환경에 설치했다. `pdfminer.six 20260107`, `pdfplumber 0.11.10`, `MarkItDown(enable_plugins=False)`, LLM/Azure 서비스 미설정의 **로컬 기본 변환**이다. OCR 플러그인 결과가 아니다. PDF 200개·GT·원본 평가기·채점 모수는 kordoc과 동일하다. 재실행 스크립트는 `bench/markitdown-bench.py`이며 제품 의존성에는 추가하지 않았다.

한국 PDF도 제조업 점검표, 가계동향, exam_social, hwpx-02, split_cell의 동일 원본을 변환해 대조했다. MarkItDown은 exam_social의 양쪽 문항을 한 행에 섞고, hwpx-02에서는 일반 본문 일부를 12열 표로 만든다. 따라서 전체 엔진 대체나 MarkItDown 결과 무조건 채택은 하지 않는다. 이 5문서 확인은 정성 분석이며 한국 전체 표/글 점수로 보고하지 않는다.
