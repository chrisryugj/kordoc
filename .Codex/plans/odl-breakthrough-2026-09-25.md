# ODL 공개 벤치 0.93+를 위한 구조 재설계 실험

## 출발점과 정직한 목표

- 고정된 외부 벤치: `opendataloader-bench` 커밋 `7af1d8f4`, PDF/GT 각 200개, 기존 평가기. kordoc 실측은 종합 **0.724617 → 0.775354**, NID **0.858758 → 0.859066**(200건), TEDS **0.597685 → 0.614082**(42건), MHS **0.417945 → 0.607309**(107건). 예측 누락 0건.
- ODL 기본형 0.831209와 하이브리드 0.906572는 같은 평가기로 **벤치 저장소의 기존 예측을 재채점**한 값이다. 외부 엔진을 이번에 새로 실행한 수치는 아니다. 최종 목표 0.93은 현재보다 **+0.154646**이 필요하며 아직 달성하지 않았다.
- 종합 점수는 문서별 적용 지표 평균의 200문서 평균이다. 현 잔여 손실 0.224646의 기여는 NID 0.092406, MHS 0.099246, TEDS 0.032994. 0.93에는 손실의 약 69%를 제거해야 한다. 제목 규칙 몇 개를 추가하거나 엔진을 갈아 끼우는 방식으로는 이 폭을 설명할 수 없다. 현 kordoc/ODL 하이브리드 출력 중 문서별 정답을 보고 좋은 쪽을 고르는 불가능한 oracle도 0.912164다.
- 한국 문서 현 기준: PDF 표 exact 2,526/2,692(716쌍), cellF1 0.963449, PDF 글 recall 0.99491(751쌍), 중첩표 exact 89.77%(176표). 외부 벤치 개선과 별도 게이트다.

현재 실패 분류에서 제목 과다 35문서가 종합 손실 0.04193, 전부 누락 10문서가 0.02417, 일부 누락 11문서가 0.01629를 차지한다. 표는 전부 누락 6문서가 0.01250, 표 개수 불일치 10문서가 0.01122, 행·열·병합 오류 8문서가 0.00701이다. 이 분류는 겹치는 원인의 귀속 방식에 따라 바뀔 수 있어 다음 실험에서 재검증한다. 제목 문구는 맞지만 Markdown `#` 레벨이 다른 43문서도 있으며, 현 MHS 평가기는 이를 점수에 반영하지 않으므로 별도 품질 지표로 추적한다.

## 첫 실험: 해법의 상한부터 측정

1. 200문서의 예측·GT·원본 PDF를 좌표와 함께 보관하고, NID/MHS/TEDS 손실을 **수정 가능한 원인**으로 분해한다. 대표 유형은 영역 간 읽기 순서, 제목 누락·과다·본문 결합, 표 누락·격자·칸 글, 텍스트층 부재다. 여러 원인이 겹친 문서는 각각의 원인 제거 실험을 별도로 기록한다.
2. 원본에서 나온 후보 블록을 사람이 일부 교정한 임시 출력으로 재채점해 각 원인군의 **상한 이득**을 구한다. 이 교정은 분석 전용이며 런타임 규칙·정답 변경에 쓰지 않는다. 개별 부품이 아닌 **통합 설계의 중복 제거 후 상한**이 +0.155에 못 미치면 제품 경로 구현을 시작하지 않는다.
3. 대표 문서 30건을 개발 표본으로 둔다. 각 코드 변경 후 200건 전체를 채점하되 문서별 정답 문구를 임계값으로 암기하지 않는다. **이번 탐색에서 이미 200건의 개별 점수를 봤으므로 이 200건 안에 진정한 잠금 표본은 없다.** 별도의 미열람 한국·비공개 PDF를 사전에 고정해 공개 벤치 과적합을 확인한다.

## 아키텍처 가설: 페이지를 하나의 영역 그래프로 복원

현재는 글자 조각 읽기 순서를 먼저 정하고 문단·표를 후처리한다. 대안은 **텍스트·벡터·이미지·OCR 후보를 같은 좌표계의 영역으로 먼저 묶고**, 표/문단/제목 경계를 정한 다음 영역 간 순서를 구하는 것이다. 영역에는 bbox, 글꼴 분포, 원본 글자 범위, 선·음영·태그 근거, 이미지 점유율, 출처, 텍스트/구조 신뢰도를 담는다. 모든 PDF에 모델을 호출하는 설계가 아니다.

1. **영역·순서 동시 추론**: 전폭 제목·그림·표가 단을 가로지를 때 이를 분리한 뒤 좌우 단과 본문을 영역 단위로 정렬한다. ODL `XYCutPlusPlusSorter`의 객체 단위 적응 절단을 동일 PDF에서 비교한다. 그래프 간선은 같은 단의 위→아래, 캡션-대상 인접성, PDF 태그 순서, 셀 소속을 사용한다. 기존 한국 괘선 표 경로는 보존하고, 새 순서기가 블록의 텍스트를 재작성하지 않게 한다.
2. **문서 전체의 제목 모델**: 글자 크기 한계값 대신 크기·굵기·서체의 희귀도, 주변 여백, 반복 머리말, 본문과의 연결, 번호 체계, 문서 전체 스타일 군집을 결합한다. 제목 후보 생성과 채택을 분리하고, 잘못 붙은 본문 분할까지 함께 고친다. 페이지 단위의 단발성 볼드 문구를 제목으로 승격하지 않는다.
3. **셀 그래프와 글자 배치 분리**: 괘선·클립·정렬 열·OCR 격자의 후보를 하나의 셀 그래프에 넣는다. 구조의 신뢰도와 칸 글의 신뢰도를 별도로 채점하여, 텍스트층이 정확하면 OCR이 찾은 격자 안에 원본 글자를 배치한다. 병합셀과 중첩표는 그래프 관계로 표현하고 Markdown 직렬화는 마지막에 한다.
4. **선택적 시각 경로**: PDF에서 관찰되는 낮은 텍스트 커버리지, 큰 미분류 이미지, 열린 격자, 열 정렬 불일치로만 OCR/시각 모델을 호출한다. 원본 글과 같은 위치의 OCR 중복을 제거하고, 글자 커버리지·셀 포함률·순서 충돌로 결과 수용 여부를 결정한다. 이미지 문서 00141에서 명시적 OCR은 33자→약 4,200자와 NID 0.020→0.667을 보였지만, 이 한 문서만으로 기본 경로를 켜지 않는다.

## 구현 전 의사결정 게이트

- 첫 실험의 산출물은 코드 변경보다 **원인별 상한·비용 표**다. 영역 그래프 순서기, 제목 모델, 셀 그래프, 선택적 시각 경로를 동일 개발 표본에서 A/B 비교한다. 각 후보의 이득이 독립인지, 서로 중복되는지 문서별 교차표로 확인한다.
- 통합 프로토타입이 종합 **0.85 이상**, NID **0.90 이상**을 못 내면 영역 경계·순서기 설계를 재검토한다. 0.90에 못 미치면 제목·표 구조와 시각 경로 중 실제 상한이 큰 쪽에 자원을 재배치한다. **0.93은 보장이나 마케팅 문구가 아니라 최종 검증 기준**이다.
- 매 변경 전에 실패 사례 회귀 테스트를 만들고, 코드 변경마다 고정 200문서를 다시 채점한다. 전체 종합/NID/TEDS/MHS, 문서별 개선·악화, 200문서 처리 시간과 최대 RSS를 기록한다. 벤치 문서 ID·정답 문구를 런타임 조건으로 쓰지 않는다.
- 한국 PDF 표 716쌍·2,692표, 글 751쌍, 중첩표 176표, HWPX/HWP5 게이트가 악화하면 원인을 밝히고 수정 전에는 기본 경로에 넣지 않는다. 기존 암호화 HWPX의 비밀번호 미상 1건은 기존 제외 모수로 별도 표시하고 변경으로 인한 실패와 혼동하지 않는다.
- OCR/모델 의존성이 생기면 CPU·오프라인 실행, 설치 크기, 첫 호출 시간과 캐시 후 시간까지 보고한다. 최종 수치는 동일 버전·입력·평가기에서 재현한 값만 사용한다.

## 2026-09-25 측정으로 구체화한 실행 계획

실측·문서별 CSV·시제품 결과: `docs/odl-breakthrough-study-2026-09-25.md`와 `docs/odl-document-deltas-2026-09-25.csv`. 세 가지 검증된 사실이 설계 순서를 결정한다.

- 제목 문구는 107건 중 103건, 표 칸 글은 42건 중 39건에서 대부분 **이미 출력에 있다**. 그러나 제목/표 경계가 무너져 MHS/TEDS가 낮다.
- 현재 글자를 자유 재배열하는 낙관적 NID 이득은 종합 +0.0344 수준이다. 영역 순서기만으로 0.93은 불가능하다. 이미지와 누락 글자, 표 직렬화도 함께 다뤄야 한다.
- 블록을 나중에 좌우로 가르는 시제품은 +0.002519(개선 4·악화 1), 표 감지 전의 열 경계를 그대로 재사용한 실험은 −0.000555(개선 0·악화 2)였다. **기존 블록/열 임계값 조정은 중단**한다. 원본 아이템 좌표와 스타일을 잃기 전의 영역 IR이 필요하다.

### 점수 예산과 중간 게이트

평가기의 진짜 산식인 **200문서의 문서별 지표 평균**으로 예산을 관리한다. 개별 지표 전체 평균을 단순 평균하지 않는다.

| 손실 기여 | 출발 | 최종 최대 잔여 | 필요한 회복 |
| --- | ---: | ---: | ---: |
| NID | 0.092406 | 0.034000 | +0.058406 |
| MHS | 0.099246 | 0.026000 | +0.073246 |
| TEDS | 0.032994 | 0.010000 | +0.022994 |
| 합계 | 0.224646 | 0.070000 | **+0.154646 → 종합 0.930000** |

이 수치는 설계별 기여를 중복 합산하지 않기 위한 **최종 손실 한도**다. 구조적으로 가능한지 Phase 0의 교정 출력과 Phase 1의 통합 프로토타입으로 검증한다. 중간 종합 게이트는 0.85, 0.90, 최종 0.93이며, 0.93 미만을 완료로 부르지 않는다.

### Phase 0 — 고정 데이터와 인과 상한 (코드 반영 전)

1. 기준 `0767b46`, ODL `7af1d8f4`, 200 PDF/GT 해시, 평가기 해시, 기본 옵션을 실행 명세에 고정한다. 현재 `bench/odl-loss-analysis.py`의 문서별 NID/MHS/TEDS 손실을 독립 재계산으로 교차검증하고 `docs/odl-document-deltas-2026-09-25.csv`를 최초 기준선으로 동결한다.
2. 개발 30건은 제목 누락/과다, 2단 교차, 표 전부 누락/격자 오류, 이미지 전용, 긴 본문 누락이 각각 들어가도록 **사전에** 선정한다. 현 손실 상위 30건은 고장 분석용으로 유지하되, 그 집합만으로 일반화 점수를 주장하지 않는다. 공개 200건은 이미 개별 점수를 열람했으므로 잠금 표본으로 부르지 않는다. 별도의 미열람 PDF 60건을 사전에 고정해 최종 일반화 검증에 쓴다. 이 자료를 확보하기 전에는 공개 200건 점수만 재현 가능한 결과로 표시한다.
3. 원본 PDF와 예측의 좌표/스타일/선/채움/이미지 증거를 나란히 보고 12~20건의 임시 출력을 사람이 **영역 경계만**, **제목 경계만**, **셀 구조만**, **시각 글만** 교정한다. 각 단독 교정과 조합을 같은 평가기로 재채점한다. 서로 겹치는 이득을 200문서 가중치로 환산한다. 기존 3건 교정의 전체 +0.007187은 이 측정의 출발점일 뿐 200건 상한이 아니다.
4. **착수 게이트:** 30건 개발 표본의 원인별 교정 효과를 200건의 관찰 가능한 후보 발생률로 투영하고, 그 통합 교정 상한이 +0.175 이상이어야 한다(목표보다 0.020 여유). 표본 외 문서의 잠재 이득을 임의로 1점 처리하지 않는다. 0.175 미달이면 영역 분할과 시각 글 복구 증거를 보강하고 다시 교정한다. 어떤 단일 부품의 상한이 작더라도 통합 필수 부품이면 배제하지 않는다.

### Phase 1 — 글자·선·이미지의 공통 영역 그래프

1. `text-line.ts`의 정규화 글자 조각에 원본 순서·폰트·bbox를 유지하고, `page-blocks.ts`의 `groupByY`/`pushLineParagraphs` **전**에 줄/단/전폭/표/그림 후보 영역을 만든다. 동일 아이템이 여러 후보에 속할 수 있게 하되 최종 셀·본문 소속은 하나만 고른다. 후보의 출처와 신뢰도도 기록한다.
2. Y 밴드 분할은 전폭 제목·표·그림을 경계로 사용하고, 밴드 안에서 단별 위→아래를 그래프 간선으로 결정한다. 표/캡션 인접, 태그 순서, 반복 머리말 제외를 추가 간선으로 사용한다. 간선 충돌은 어떤 근거가 졌는지 진단에 남긴다. 글자 자체는 재작성하지 않는다.
3. `040`·`043`의 탭 결합, `191`의 학술 2단, `010`·`015`의 이미지와 본문 혼합을 별개의 개발 사례로 둔다. 현재 블록 후처리가 5건만 건드린 원인은 각 줄의 좌우 좌표가 블록 하나로 합쳐졌기 때문이다.
4. **게이트:** 개발 사례에서 원본 텍스트 보존율 ≥99.5%, NID 손실 기여가 0.092406→≤0.065, 전체 종합 ≥0.80. 200건에서 개선·악화 ID와 크기를 출력한다. 한국 PDF 글 recall 0.99491·표 exact 2526/2692 미만이면 기본 경로에는 넣지 않는다. 도달하지 못하면 `groupByY` 이전의 영역 경계와 셀 소속 문제를 다시 설계한다.

### Phase 2 — 문서 전체 제목·본문 경계 모델

1. 영역의 각 **줄**에 폰트 크기·서체·굵기·색/채움·주변 여백·폭·페이지 위치를 남긴다. 문서 전체 빈도로 본문 스타일과 희귀 제목 스타일을 군집화한다. 페이지별 첫 제목 유무로 다른 후보를 일괄 건너뛰지 않는다.
2. 후보 생성(크기/스타일/번호 체계)과 채택(반복 머리말/캡션/본문 연결/다른 페이지의 같은 스타일)을 분리한다. 결합된 제목+본문은 줄 경계에서 분리하고, 제목 텍스트를 새로 만들지 않는다. MHS는 레벨을 무시하지만 실제 `#` 위계와 문구 정확도를 별도 기록한다.
3. **게이트:** 제목 과다 35·전부 누락 10·일부 누락 11건의 개선/악화 표를 만들고, 전체 MHS 손실 기여 ≤0.050, 종합 ≥0.85. 문서별 MHS만 올리고 NID를 떨어뜨린 후보는 채택하지 않는다. 한국 공문서 마커 제목과 HWPX/HWP5 결과가 변하면 원인을 제거한다.

### Phase 3 — 셀 그래프, 본문 글자 재배치, 직렬화

1. 괘선 Vertex, 클립, 행별 채움, 수평 정렬 열, OCR 격자를 공통 셀 후보 그래프에 모은다. **1열 다행도 표 후보**로 유지하고, 외곽 선의 연결과 행별 내용 반복으로 서식용 1열 박스와 구별한다. `149`는 현재 그리드 처리에서 1열 다행을 건너뛰고 Markdown 빌더가 1열 IR을 평탄화하는 양쪽 경계의 증거다.
2. 구조 신뢰도와 셀 글 신뢰도를 분리한다. 텍스트층이 정확한 영역에서는 그 글자를 새 셀의 bbox에 배치한다. OCR은 격자 근거로만 쓰고 원본 글자를 덮지 않는다. 병합/중첩 관계는 그래프에 남겨 최종 직렬화에서만 HTML/Markdown을 고른다.
3. **게이트:** TEDS 손실 기여 0.032994→≤0.010, 42건의 구조/글 점수와 표 개수 변화를 모두 보고한다. 한국 표 exact ≥2526/2692, cellF1 ≥0.963449, 중첩표 exact ≥89.77%(176표), PDF 글 recall ≥0.99491. 한 문서의 TEDS 향상으로 한국 서식 표가 평탄화되면 경로를 되돌린다.

### Phase 4 — 선택적 시각 경로와 실제 0.93 통합

1. 기존 OCR 트리거 3건의 이득은 종합 +0.003115, `141`은 약 1 GB RSS/3.21초다. 새 트리거는 PDF **영역별** 텍스트 커버리지, 큰 미분류 이미지, 열린 격자, 셀 글자 미배정 비율, 순서 충돌만 사용한다. 문서 ID·정답 문구는 사용하지 않는다.
2. 낮은 신뢰 영역만 래스터하고 OCR/시각 후보를 원본 글자와 bbox 단위로 대조한다. 새 글자/셀/제목을 받아들이려면 출력 글자 커버리지 증가와 중복률/순서 충돌 감소가 함께 관찰되어야 한다. CPU·오프라인 설치, 첫 호출/캐시 후 시간, 최대 RSS를 기록한다.
3. 통합 후 손실 예산(NID ≤0.034, MHS ≤0.026, TEDS ≤0.010)을 하나씩 확인한다. **0.90 미만:** 영역+제목 경계를 재설계. **0.90 이상 0.93 미만:** 잔여 손실 기여 상위 문서군으로 시각/표의 추가 상한을 다시 구한다. 공개 문서별 임계값 미세 조정은 하지 않는다.
