# ODL 0.907 초과를 위한 PDF 파서 설계

## 현재 실측과 필요한 개선량

- 고정 코퍼스: `opendataloader-bench` `7af1d8f4`, PDF/GT 각 200개. 평가기와 GT는 변경하지 않는다.
- kordoc 16a98f8: 종합 0.724617, NID 0.858758, TEDS 0.597685, MHS 0.417945.
- 이 브랜치의 기하학적 제목·열 표 수정: 종합 0.775189, NID 0.859050, TEDS 0.614082, MHS 0.606747.
- 같은 평가기에서 벤치 저장소의 **기존 예측 파일을 재채점**한 OpenDataLoader 점수: 기본형 0.831209, 하이브리드 0.906572. 두 외부 파서를 새로 실행한 값은 아니다.
- 최고점을 **분명히** 넘는 검증 목표는 0.93 이상이다. 현재 필요한 종합 개선량은 최소 0.154811이다. 남은 오차 기여는 NID 0.092421, TEDS 0.032994, MHS 0.099397이다. 이 세 값은 문서별 적용 지표 수로 가중한 종합 점수 손실이며, 전체 지표 평균을 임의 합산한 값이 아니다.
- 현 kordoc와 ODL 하이브리드 출력에서 문서별 더 좋은 쪽을 정답을 보고 고르는 불가능한 oracle도 0.912164다. 단순 엔진 전환 또는 선택만으로 0.93은 불가능하다.
- 양쪽 모두 낮은 문서가 우선 원인 분석 대상이다. 예: `00141`(각각 종합 0.010/0.000), `00107`(0.231/0.219), `00062`(0.496/0.499), `00103`(0.537/0.485), `00183`(0.469/0.566). 이는 진단 목록이지 런타임 문서 ID 분기가 아니다.
- `00141`은 거의 전부 이미지인 저작권 인포그래픽이다. 현 기본 파싱은 33자, NID 0.020/MHS 0이다. 현 내장 OCR을 **별도 실험에서 명시적으로 켰을 때** 4,200자, NID 0.667/MHS 0.385가 나왔다. OCR만으로도 복원되지만 표·제목의 잘못된 분할은 남는다. 기본 경로에 OCR을 무조건 켜면 된다는 근거는 아니다.

## 목표 파이프라인

```text
PDF 페이지
  ├─ 텍스트층: 글자·폰트·태그·좌표
  ├─ 벡터층: 선·채움·클립·이미지 위치
  └─ 선택적 래스터: 저텍스트/표 구조 불명 영역만 OCR·시각 모델
       ↓
영역 후보(문단·제목·표·그림·캡션) + 좌표/출처/신뢰 신호
       ↓
중복 글자 제거 → 셀 그래프 확정 → 영역 간 읽기 순서 그래프
       ↓
문서 전체 제목 스타일 군집 → IRBlock[] → Markdown
```

영역 후보는 `bbox`, 추출된 원문 범위, 원본층/시각층 출처, 텍스트 커버리지, 선/정렬 근거, 중복 영역을 갖는다. 네이티브 텍스트와 OCR이 같은 위치에 있으면 둘을 모두 방출하지 않고 글자 커버리지와 위치 일치로 하나를 고른다. 표 구조와 셀 글은 별도 신뢰도로 채택한다. 예를 들어 OCR이 셀 격자는 더 잘 찾지만 글자는 텍스트층이 정확하면, 격자는 OCR에서 가져오고 셀 글은 위치로 정렬한 텍스트층에서 가져온다. 이 방식은 문서 전체를 다른 파서 출력으로 바꾸지 않는다.

## 구현 경로

1. **레이아웃 증거 통합.** 텍스트 조각, 선, 채움, 이미지, 글꼴 크기·굵기·이름, PDF 태그를 같은 페이지 좌표계의 영역 IR로 만든다. 문단 분리 전에 단과 표 경계를 추론하고, 분리 뒤 블록 순서를 정한다. 현재 `xy-cut`의 글자 조각 단위 순서와 ODL `XYCutPlusPlusSorter`의 객체 단위 적응형 절단을 같은 실패 문서에서 비교한다. 교차 영역(전폭 제목·그림 캡션)을 분리한 뒤 단별 순서를 복원하는 알고리즘을 포팅하되 기존 한국어 괘선 표 경로와 충돌하지 않도록 영역 단위로 적용한다.
2. **제목 확률과 위계.** 현재 글자 크기 비율·희귀 글꼴 보정은 후보 생성이다. 후보마다 주변 공백, 글꼴 굵기, 크기·굵기의 문서 내 희귀도, 행 길이, 본문 연결, 반복 머리말 여부를 계산한다. ODL `HeadingProcessor`가 쓰는 `headingProbability`와 희귀도 신호를 참고하되 판정은 kordoc IR에 맞게 구현한다. 본문 글꼴과 같은 제목 및 리스트로 잘못 묶인 제목을 별도 처리한다. 스타일 군집으로 수준을 정하고, 제목 문구와 뒤따르는 본문의 결합 오류를 같이 측정한다. GT 문구나 문서 ID 규칙은 사용하지 않는다.
3. **표의 두 층 복원.** 선·클립·음영 격자와 정렬 열 후보를 공통 셀 그래프로 합친다. 수평선만 있는 무괘선 서구식 표, 이미지 표, 한 열의 의미적 표를 구별한다. 구조(행/열/병합)와 텍스트 인식의 신뢰도를 따로 계산한다. 이미지 표는 PDF 텍스트층이 해당 영역에 거의 없을 때만 로컬 OCR/표 구조 모델로 보완하고, OCR 셀을 PDF 좌표와 정렬한다. 전체 문서를 모델 출력으로 바꾸지 않는다. 표 외 prose는 텍스트층의 원문 순서를 보존한다.
4. **선택적 시각 백엔드.** OCR/시각 모델은 낮은 텍스트층 커버리지, 열린 격자, 열 정렬 불일치, 큰 미분류 이미지 등 PDF 자체 신호로만 라우팅한다. 별도 명령·모델 파일 의존성을 분리하고 기본 설치의 성능과 한국 공문서 기준선을 지킨다. 후보 결과의 텍스트 커버리지·셀 그래프 일관성·위치 일치로 수용 여부를 결정한다. 벤치 GT나 평가 점수로 런타임 선택하지 않는다.

순서 그래프의 간선은 같은 단의 위→아래, 표·캡션 인접성, 전폭 블록의 앞뒤, PDF 태그 순서를 근거로 만든다. 서로 모순되는 간선은 글자 순서가 아니라 지면 영역 신뢰도와 분할 일관성으로 해소한다. 현재처럼 표를 포함한 페이지 전체를 한 문단으로 만들어 NID가 떨어지는 경우를 영역 경계에서 막는다.

시각 경로의 수용 조건은 벤치 기반 고정 임계값이 아니라 PDF 관찰값의 일관성 검사다. 구체적으로 원본층의 글자 수/범위, OCR 글의 동일 위치 중복률, 각 셀 글의 셀 내부 포함률, 열 경계의 행 간 일치율, 인접 문단과의 순서 충돌 수를 측정한다. 이 검사를 통과하지 못한 후보는 원본 경로를 유지하고 불확실성을 경고한다. OCR 실패가 정상 문서의 텍스트층을 덮어쓰지 못하게 한다.

이 순서는 ODL 기본형의 객체 단위 `XYCutPlusPlusSorter`·`HeadingProcessor`와 하이브리드의 선택적 AI 백엔드를 코드 수준에서 대조해 세웠다. 기존 kordoc는 클러스터 표 감지 등 일부를 단순화해 포팅했으며, 현재 표 점수는 기본 ODL보다 높다. 따라서 전체 결과를 외부 엔진으로 바꾸는 방식은 설계에서 제외한다.

## 검증 순서와 완료 조건

- 각 단계 전에 실패 PDF의 재현 테스트를 만든다. 200문서 전체를 매 변경마다 재채점하고 문서별 개선·악화, 종합/NID/TEDS/MHS, 시간/RSS를 기록한다.
- 단계 1의 성공 기준은 NID가 오른 문서의 개선폭 총합이 악화폭보다 크고, 긴 본문을 표로 오인한 문서가 0건인 것이다. 단계 2에서는 제목 전부 누락 10건뿐 아니라 추가 제목 35건과 부분 누락 11건을 각각 낮춰야 한다. 단계 3에서는 남은 표 누락 6건, 표 개수 불일치 10건, 행열·병합 8건을 별도 집계한다. 단계 4는 이미지 문서 `00141` 외 다른 문서/한국 코퍼스에서도 발동률·정확도·비용을 확인한 뒤 기본 경로에 넣는다.
- PDF 표 716쌍·2,692표, PDF 글 751쌍, 중첩표, HWPX/HWP5 게이트를 같은 빌드에서 확인한다. 점수 향상을 위해 정답·평가기·모수 제외 규칙을 변경하지 않는다.
- 속도 목표는 텍스트층이 충분한 PDF의 200문서 총시간을 현 7.0초 수준으로 유지하는 것이다. 시각 경로는 대상 영역/페이지 수와 별도 처리 시간을 함께 보고한다. 모델 의존성을 추가한다면 설치 크기와 오프라인 동작도 게이트에 포함한다.
- 0.93을 설계 목표로 두되 달성이라고 보고하는 조건은 **실측 종합 0.93 이상**, NID·TEDS·MHS 각각의 변화, 한국 문서 무후퇴, 시간·메모리 한계를 모두 제시한 경우뿐이다. 현 브랜치의 0.775189는 이 조건을 충족하지 않는다.
