# Python SDK Changelog

## Unreleased

- **동작 변경**: `max_worker_rss_bytes` 로 워커를 바꿀 때, 같은 슬롯의 다음 요청은 이전 워커의 종료·회수가 끝난 뒤 새 워커를 띄웁니다. 보통은 바로 끝나지만 워커가 quit 에 응하지 않으면 `close_timeout`(기본 10초)에 강제 종료 정리 3초를 더한 만큼까지 기다리며, 이 대기는 요청 제한 시간에 들어갑니다.
- **동작 변경**: `worker_pids()`·`worker_info()` 가 ready 전이거나 종료를 기다리는 중이어도 살아 있는 소유 워커를 포함합니다(ready 전 워커는 버전·rss 가 없을 수 있습니다).
- 취소·실패한 요청의 워커도 종료·회수가 끝난 뒤 같은 슬롯의 교체 워커를 띄웁니다. 회수 작업이 예외·취소로 끝나도 그 슬롯의 이후 요청에 그 예외를 다시 던지지 않고, 이전 워커가 남아 있으면 먼저 끝냅니다.
- 동기 클라이언트는 시작하지 못한 루프를 그 루프에 넘긴 마지막 호출이 끝날 때 한 번 멈춥니다. 실패한 `start()` 가 다른 스레드의 성공한 시작을 멈추지 않고, 같은 시작을 기다리다 함께 실패한 호출이 있어도 루프 스레드를 남기지 않습니다.
- 닫기가 이미 끝난 회수 작업을 되풀이해 기다리며 멈출 수 있던 문제(Python 3.12+)를 고칩니다. 워커를 강제 종료할 때 파이프를 물려받은 자손 프로세스는 기다리지 않습니다(1초 뒤 우리 쪽 파이프를 닫습니다).
- 확보한 독립 워커의 워밍업을 병렬로 실행하며 보고서 순서와 교체 워밍업 규칙을 유지합니다. 실패·취소 시 모든 워밍업과 종료 정리가 끝난 뒤 슬롯을 반환합니다.

## 0.2.1 — 2026-10-21

- 블록 단위 검수 `lint_blocks(blocks, **options)` — 문단·표 칸을 id 가 붙은 블록으로 넘기면 지적을 블록 id·블록 안 위치로 돌려줍니다. npm kordoc 엔진 4.24.0 이상이 필요합니다(희소 표·예산 검산 수정은 4.24.1).
- 워커 요청 한 줄 기본 상한을 1MiB 에서 8MiB 로(`max_request_bytes`), 엔진 기본값과 같게.

## 0.2.0 — 2026-10-16

- OCR 줄·상자·신뢰도 내보내기(`ocr_lines`)와 검출 모델·해상도·로컬 인식 모델 선택을 지원합니다. `OcrModelFile`, `OcrPageLines`, `OcrLine`, `OcrBox` 타입을 제공합니다. 새 OCR 기능은 npm kordoc 엔진 4.22.0 이상이 필요합니다.
- 동시 시작·종료, 워커 교체·warmup 중 취소, timeout 후 복구 및 임시 파일 정리를 보완했습니다. Python 3.14에서 동기 `close()`가 시작되기 전에 Ctrl-C로 중단되어도 워커를 종료합니다.
- NaN·Infinity 등 JSON으로 보낼 수 없는 옵션과 존재하지 않는 엔진 경로를 워커 실행 전에 거부합니다.

## 0.1.0 — 2026-10-10

- 상주 엔진 워커를 사용하는 동기·비동기 Python SDK 최초 배포.
